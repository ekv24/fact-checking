# Интерфейс (пункт «Интерфейс», 10 баллов)

Веб-интерфейс на Streamlit. Код — в `app/`, тесты — в `tests/ui/`. Пока подключена **заглушка агента**:
вердикты случайные, поэтому в интерфейсе об этом написано.

## Запуск

```bash
pip install -r app/requirements.txt
streamlit run app/streamlit_app.py
python -m pytest -q tests/ui
```

## Пользовательский путь

1. Загрузить таблицу CSV (или добавить одну запись формой, или нажать «Загрузить пример»).
   Обязательные столбцы: `person`, `event_type`, `date`; по желанию `source_url`, `quote`.
   Допустимы русские названия столбцов, разделитель `,` или `;`, кодировка UTF-8 или Windows-1251.
2. Проверить предпросмотр и нажать «Проверить». Пока агент работает, виден прогресс по записям.
3. Вкладка «Записи»: счётчики по четырём вердиктам, фильтр, карточка каждой записи
   (вердикт, уверенность, подтверждающие и опровергающие свидетельства с цитатами и надёжностью,
   раскрывающийся блок «как агент пришёл к выводу»), выгрузка результатов в CSV.
4. Вкладка «Возможные пропуски»: события, найденные в документах, но отсутствующие в таблице.
   Это кандидаты для ручной проверки.

## Контракт с пайплайном

Интерфейс общается с агентом только через `app/agent_api.py::check_records(records)`.
Функция принимает список `Record` и возвращает итератор событий из `app/schemas.py`:
`StatusEvent` (текст прогресса), `ResultEvent` (результат по одной записи), `GapEvent` (пропуски, в конце).
Вердикты: `supported`, `refuted`, `not_enough_info`, `conflict`.
Чтобы подключить настоящий пайплайн, достаточно заменить тело `check_records`.

## Обработка ошибок

| Ситуация | Поведение |
| --- | --- |
| Пустой файл, нет обязательных столбцов, неверная кодировка | Сообщение с объяснением, приложение не падает |
| Строки с пустыми обязательными полями | Строки пропускаются, номера показаны пользователю |
| Больше 50 записей или файл больше 1 МБ | Отказ с понятным сообщением |
| Сбой на одной записи | Карточка «не удалось проверить», остальные результаты сохраняются |
| Исключение в пайплайне | Ошибка в интерфейсе и в логе, готовые результаты остаются |

Логи пишутся в `app/logs/app.log` (в `.gitignore`).

## Соответствие критериям курса

- Интерфейс подключён к полному пайплайну (4): после замены заглушки — через `agent_api.py`.
- Надёжность (3): проверка ввода, лимиты, изоляция сбоев, тесты `tests/ui`.
- Понятность новому пользователю (3): описание задачи на экране, пример данных, подсказки по столбцам,
  индикатор прогресса, пояснение, что такое «возможные пропуски».
