## Предложение для первой оценки

Предложение для обсуждения командой. Числа — ориентиры для статистической различимости, а не согласованный объём.

**Объект оценки.** Датасет биографических событий, уже собранный AI-агентом для исследования участника команды. Единица оценки — запись-событие (человек, тип события, дата с указанием точности, источник, цитата), то есть проверяемое утверждение.

**Эталон.** Стратифицированная выборка людей: с событиями и без, с Википедией и без, разные подгруппы. Для них размечаем:
- верность каждой записи по независимым источникам;
- все события в полных текстах выбранных документов, включая документы без событий;
- противоречия между источниками, которые сохраняем явно.

Ориентир — не меньше 150 размеченных записей, второй разметчик на 20–30% выборки с расчётом согласия. Размечает не исследователь-пользователь. Правила совпадения дат (день, месяц, год, приблизительная дата) и разрешения идентичности фиксируем до разметки. Эта разметка одновременно закрывает независимую проверку, которую требует протокол самого исследования.

**Трек B — вердикт (метрики курса).** На вход подаются записи-кандидаты: реальные записи датасета и записи с внесёнными ошибками (сдвиг даты, однофамилец, событие, которого нет в источниках). Ориентир — около 300 кандидатов. Вердикты: «подтверждается», «опровергается», «недостаточно данных», «противоречие источников». Метрики:
- точность вердикта и macro-F1;
- доля действительно подтверждающих ссылок вместе с долей отказов от вердикта;
- доверительные интервалы.

**Трек A — пропуски.** Полнота существующего датасета и доля пропусков, найденных инструментом, относительно эталона по полным текстам. Пропуски ищем так: извлекаем события из каждого документа независимо и сверяем с таблицей кодом. Просьба к LLM «найти, чего не хватает» по литературе работает плохо.

**Смещение покрытия.** Полнота и точность по подгруппам: известность, наличие Википедии, пол, период. Обнаруженный перекос для научного вывода важнее средней метрики.

**Бейзлайны.**
- существующая модельная проверка агента;
- ассистент с теми же документами (Claude/GPT с файлами или NotebookLM);
- один промпт той же модели;
- открытая система фактчекинга (Loki/OpenFactVerification).

Абляции: без документов (проверка на знание модели о известных людях) и без независимых источников (проверка «тем же фрагментом»).

**Практическая польза.** Время человеческой проверки одной записи с инструментом и без него, на разных подвыборках людей. При n = 1 это кейс, а не обобщаемая метрика.

**Данные.** Отправка во внешний API разрешена пользователем. Данные исследования не хранятся в публичном репозитории, публикуются только агрегированные метрики. Для публичного демо и тестов готовим отдельный небольшой набор на открытых биографиях.

Поиск источников за пределами корпуса оцениваем отдельно: можно считать новые подтверждённые находки, но нельзя вычислить полноту всей биографии. LLM-судья не заменяет ручной эталон и допустим только после сверки с ним.

Продолжение работы оправдано улучшением качества при сопоставимых затратах либо сокращением времени при сопоставимом качестве. Числовой порог выбираем до эксперимента.

## Что нужно закрыть перед сдачей

- Состав команды, роли и ментор.
- Список людей, тип событий, язык и документы для первого корпуса.
- Реально сохраненные данные: количество документов/записей, формат и путь.
- Правила выбора источников, единица события и разрешение противоречий.
- Подход к поиску, модель и минимальный интерфейс.
- Размеченная выборка, правила метрик и критерий полезного улучшения.

Polymarket и бэктест не входят в обязательства этого чекпоинта. Полные требования курса — в [контексте проекта](../project-context.md).
